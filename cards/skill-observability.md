# 流程卡：skill-observability（Skill 合规可观测平台）

## 路径判定
- 判定：跨会话大任务
- 路径：wayfinder
- 理由（三问判据）：
  1. 说得清怎么做吗——否：平台边界（采集/策略/看板范围、业界方案、Trace 数据模型）尚未收窄，有迷雾；
  2. 单个会话能规划完吗——否：2-3 个月、多模块（采集端 / 存储 / 策略引擎 / 查询 API / 看板），必须跨会话；
  3. 几行改动、肉眼可验证吗——否：非微小改动。
- 任务背景：面向「AI 大模型应用 / agent 开发工程师」岗位的简历项目；单人 + AI 会话开发；预算 2-3 个月；交付标准 = 面试可现场演示、可被追问出深度。

- 一票一新会话，票间 clear；开工先读本卡对齐
- HITL 票（prototype / grilling / task）必须用户在场逐问拍板，agent 自答问题 = 违规，叫停重开

## 流程序列（12 维，导师起草用户审改）
| 维度 | 选择 | 理由 |
| --- | --- | --- |
| D1 前置探索 | 调研（短调研扫盲） | 业界方案（Langfuse/LangSmith）与 Trace 数据模型没摸清，先扫盲，产出喂回路径判定 |
| D2 形态设计 | 低保真原型 | Trace 看板/审计页涉及 UI，门禁二必过原型；低保真先对齐信息架构，成品 UI 质感在实现票与 D8 里打磨 |
| D3 实现顺序 | 垂直交错 | 每票纵贯采集→存储→查询→看板，落地即可演示，避免长期"后端全好但无可见产出" |
| D4 测试策略 | 只测关键路径 | 策略引擎与采集去重是判定核心，红绿覆盖；看板走 QA 实测；全面 TDD 拖慢单人节奏 |
| D5 QA 节奏 | 每票 QA | 代码主要由 agent 实现，漂移风险高，每票亲手点一遍，问题早回流 |
| D6 交付形态 | 演示优先 | 面试场景要现场跑 demo；非生产型项目不走部署发布，需要时再改卡 |
| D7 会话编排 | wayfinder 地图 | 与路径判定一致（说不清 + 超会话） |
| D8 文档与交付物 | README 每里程碑更新；验收前出演示材料 | 面试官先看 README；走查脚本 + 截图/GIF 支撑面试讲解 |
| D9 优化与维护 | 重构（/retro 触发，里程碑后落位） | agent 长跑代码熵增快，复盘后集中重构，防积重难返 |
| D10 环境与基建 | CI 最小集（lint + 类型检查 + 关键路径测试，push 触发） | 简历加分项，同时拦截 agent 提交的坏代码 |
| D11 安全与合规 | 密钥权限开工即执行（API key 走环境变量，不进 git/prompt）；验收前一轮集中安全审查 | 项目本身是合规平台，密钥管理是基本盘 |
| D12 性能压测 | 验收前一次小规模压测（如 1k span/s 采集），产出吞吐数字 | 量化数字直接进简历；一次即可，不需容量规划 |

## 预设来源
调研驱动型（D1 调研 → 重新判定路径 → 转垂直交错型）；D5、D12 为超出预设的自选（已标注）。

## 不可选区确认
- 五件套（决策留人、可见产出、问题即工单、评审换上下文、验收签字）与依赖护栏（原型先于开发、验收标准先于实现、联调在两端可跑后、部署在验收后）已内置，不参与选择；用户要求越界时留痕说明。
