## 功能描述

把 M1 第一条端到端竖线打穿并可演示：`python demo.py` 一条命令，进程内起 FastAPI（对齐 #8 同进程决议），以 replay 档跑客服场景第一拍「查订单（allow）」——`invoke_agent → chat → execute_tool` 三层树，execute_tool 八步时序全链（#8）落 span / event_log / audit，SSE 推送，终端打印走查询 API 拉回（不直读 DB）。

- 策略引擎按契约实装**全语义**（两原语 AND、block/audit、priority、agent_ids 作用域、内存快照 + rules_version 启动加载），种子 4 条播种——不留桩：查订单的 allow 是真实求值产物（4 条种子评估后未命中）。
- SDK 三原语（agent_run / chat / execute_tool 八步 + 被拦七步分支、contextvars、PolicyBlocked）**一次成型**；本拍场景只演练 allow 分支。
- **demo.py 生命周期（本票钉死，#10 人验5 的唯一自洽机制）**：
  - `python demo.py`：起服务 → 自动跑一遍场景 → 打印（树 + 本 run 审计）→ **进程不退出**，提示「回车重跑 / Ctrl+C 退出」。
  - 回车 = **同进程内**重跑（新 trace、DB 累积、SSE 续推）。不允许「再开一个 `python demo.py`」：会端口冲突，且 #8 决议 4 已把跨进程推送延期，第二个进程写的 span 不会出现在第一个进程的 SSE 流里。
  - 人验5 流程：先跑一遍 → 另开终端 `curl -N http://127.0.0.1:8000/api/events` → 首连收到全量回放（契约 §3.1）→ 回车重跑 → curl 实时收到新 run 的 span.start / span.end。
  - pytest 不走交互循环：交互包装只属于命令行入口，场景运行暴露为可导入的函数 / ASGI app。

## 验收标准

- [ ] `python demo.py` 一条命令完成第一拍全链，进程保持存活、回车重跑生成第二个 trace（#10 人验1 机制定型）
- [ ] 另开终端 `curl -N /api/events`：首连全量回放 event_log、回车重跑实时收到新 span.start/span.end（= #10 人验5，机制定型）
- [ ] `GET /api/traces` 返回该 trace（span_count ≥ 3）；`GET /api/traces/{id}` 平铺数组按 parent_span_id 可建三层树（#10 机验8 的 API 基础）
- [ ] 首跑后 `GET /api/audits` 查到恰一行：verdict=allow、rule_id=NULL、payload 为已解析 JSON、含 trace_id/span_id（#10 人验4① 的数据基础）
- [ ] 引擎种子 4 条生效且查订单未被误命中：该工具 span 无 verdict/matched_rule 属性（#10 机验6 allow 侧）
- [ ] event_log 条数 = span 数 ×2；span end 后 UPDATE 补时长（SSE 回放流可数）（#10 机验7 的数据基础）
- [ ] 断网 / 无密钥重跑输出可重复（replay 档；match_on 含 body，请求序列化确定性：temperature 固定、prompt 与工具 schema 顺序稳定）
- [ ] 自查：无 React、无规则 CRUD 端点

## 可见产出

- 类型：真实命令输出
- 怎么看到它：终端 1 `python demo.py`；终端 2 `curl -N http://127.0.0.1:8000/api/events`（回车重跑看实时流出）；`curl -s http://127.0.0.1:8000/api/traces`、`curl -s http://127.0.0.1:8000/api/audits` 原始输出贴票

## 边界

- 场景只跑第一拍（查订单 allow）；观察期 / 拦截两拍归子票 2（代码分支已就位但场景不触发）
- 不做：规则 CRUD / 热生效写路径（→M2）、React、统计、运维场景、live 档与 API 失败降级、Last-Event-ID 前端续传
- cassette 为粗糙版（开发期录制或手写皆可，#10 原文允许两者），#9 定稿后重录/调整，不阻塞本票
- 端口默认 127.0.0.1:8000，demo 启动时打印实际地址；运行期 SQLite 文件与 `__pycache__` 入 .gitignore
- `requirements.txt` 逐包 `==` 钉死版本，不装最新版：fastapi 取 ≥0.135（原生 SSE 支持，research/stack-spike 已验证），vcrpy 按 #5 结论（httpx 拦截、match_on 含 body）；uvicorn / openai / httpx 等同样钉死
- **逃生阀**：若单会话装不下——停下，报告已完成部分与缺口清单，不留桩、不半实现

## 涉及模块

- `skill_observability/db.py`：DDL 五表（span / event_log / audit / rule / meta，契约 §1）+ 从 seed/rules.json 幂等播种
- `skill_observability/engine.py`：evaluate 纯函数全语义（契约 policy §1.3/§1.4）+ 快照 / rules_version 启动加载（§2，M1 无写路径）
- `skill_observability/sdk.py`：agent_run / chat / execute_tool（#8 八步 + 被拦七步）、contextvars、PolicyBlocked
- `skill_observability/sse.py` + `api/events.py`：event_log 写入（span 落库 / UPDATE 后、广播前）→ 同进程广播 → `GET /api/events`（回放 + 实时，契约 §3）
- `skill_observability/api/traces.py`、`api/audits.py`、`app.py`：查询 API×3（契约 trace §2、policy §3.2 原样）
- `scenario/customer_service/`：config（系统提示词 + 工具清单 + 预置数据）、tools、agent（**通用多轮工具循环**，chat 包住整轮——工具 span 是 chat span 的子 span，树三层）、llm（replay 档客户端）
- `scenario/cassettes/customer-service.yaml`：第一拍 cassette
- `skill_observability/printing.py`：基础缩进树（三层、时长、状态）+ 本 run 审计行打印（数据均走查询 API）
- `demo.py`：单命令入口 + 生命周期（如上钉死）
- `seed/rules.json`：契约 policy §1.6 四条，内容一字不改
